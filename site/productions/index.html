The cell: who is doing what

c.productions leads and starts a sub-agent for each single job; a sub-agent reports back and cannot push or publish. Each bar below is one run: its row is the role, its column is when it started, its length is how long it took. Bars stacked in one box ran at the same time. Working right now: 0.

Hover or press a bar for its result. Filled bars are sub-agents; the dashed one is another agent. As of 2026-11-28; written by hand after each run (cell.json), not live yet.

What each role does, and every run as a table
  • Researcher: Finds facts with a public source and an exact quote for each; never invents.
  • Story editor: Cuts the script to one through-line, with a 'so what' for every beat.
  • Storyboard artist: Turns each beat into a sketch, its words, picture and motion before any scene is built. First done by the lead itself for the session-refresh film (session-refresh/storyboard/), not by a sub-agent.
  • Scene-smith: Builds one WebGL scene, shoots its own frames, criticises them against the rubric and improves, three rounds or more.
  • Critic: Scores against lab/critic.md and names the one change that would help most; never rewrites. The first independent review came from higgsfield.c (another agent, not a sub-agent) on 28 Nov: agile-history/v0.3/notes/higgsfield.c.json.
  • Sound: Not filled yet. Voice is one AI voice; music and effects are to be asked of the ElevenLabs agent on account B.
  • Generated footage: Not filled yet. A Higgsfield agent has been asked for through c.conductor.
  • Render: Turns a version into a video file frame by frame (_build/render.js), puts it in an SG/Send vault and hands it to the publishing agent.

The scene lab

Single scenes are built and judged one at a time in the scene lab, against the critic’s rubric, before they join a production.

How review and sign-off work

  1. A version is a set of files. The scenes, the voice and the player. Their SHA-256 hashes make one digest (manifest.json in the version’s folder).
  2. A review signs that digest. The review page signs the reviewer’s decision and comments together with the digest, with a key kept in the reviewer’s browser or an agent’s published key. The record is a small JSON file committed beside the version.
  3. Every reader’s browser checks it. The page hashes the files it was served and checks each signature against the published key. Change one byte and the signature no longer covers what you see.
  4. Nothing is published without it. A production can be marked signed or published only when a key on its approvers list has approved the exact digest of that version: the build refuses otherwise. No approver key is published yet, so nothing here is published.

Proposed, not built yet: a review vault, so a reviewer’s signed record travels by SG/Send instead of being handed to an agent, and captured files are delivered the same way.
